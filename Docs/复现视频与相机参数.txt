二、通过 UE 界面重新输出双视角视频

此流程不需要 Python，不需要临时作者脚本。

1. 打开工程和 L_GolfPractice，确认当前未处于 Play 运行状态。
2. 在“编辑 > 插件”确认内置 Movie Render Queue（MovieRenderPipeline）已启用。
   工程文件已记录该依赖；若修改插件启用状态，按 UE 提示重新启动编辑器。
3. 打开“窗口 > 过场动画／Cinematics > Movie Render Queue（影片／电影渲染队列）”。
4. 载入已保存的队列 /Game/GolfHeadCam/RenderPresets/Q_GolfViews。
   队列包含 Golf_FirstPerson 和 Golf_ThirdPerson 两个任务。
5. 确认两个任务分别使用：
   /Game/GolfHeadCam/Sequences/LS_Golf_HeadCamera
   /Game/GolfHeadCam/Sequences/LS_Golf_ThirdPerson
   地图均为 L_GolfPractice；设置取自 MRQ_Golf_1080p60。
   队列保存的是各任务的配置快照，界面可能显示自定义／未保存配置，而不是动态链接的预设名称。
   直接使用队列中的配置即可；不必再次套用预设，以免将两个独立输出目录覆盖成通用目录。
6. 打开任务设置核对 Output 分辨率、帧率、输出目录，以及 PNG 和 H.264 MP4 两种输出。
   H.264 采用 CRF=18，不写音轨。目录分别为工程下 Output/FirstPerson 和 Output/ThirdPerson。
   Game Overrides 使用 BP_GolfRenderGameMode，避免交互 HUD 或默认 MRQ 模式隐藏人物。
7. 点击 Render (Local)／本地渲染。等待队列完成后检查日志和生成文件。
8. 打开 MP4 播放；核对起始准备、击球附近和完整收杆，并检查两个视频的分辨率、帧率与帧数一致。

如果队列资产未载入，也可在 MRQ 使用“+ Render／添加渲染”逐一加入上述两个 Level Sequence，
在各自设置中加载 /Game/GolfHeadCam/RenderPresets/MRQ_Golf_1080p60，指定同一地图和各自输出目录。
保留序列的原始播放范围，不额外缩短或增加 Handle Frames。

序列时间设计（秒）
  视频 [0,1]：CinematicTime=0，准备停留。
  视频 [1,5]：CinematicTime 从 0 线性变到 4，完整播放同一动作。
  视频 [5,6]：CinematicTime=4，收杆停留。
  动作触球 2.25 s 对应名义视频时间 3.25 s；按 60 fps 为名义第 195 帧。
  帧编号从 0 开始。动作与电影时间的运行采样最大误差约 1.113e-7 s；帧与动作对应以保存的序列及采样为依据。
两条序列显式控制 CinematicMode、CinematicHeadView、CinematicTime 、球飞行开关和 ShowBallTrajectory=true。轨迹属性使用 Restore State，普通交互仍默认关闭。
主动作序列使用无畸变基线，并关闭校验网格；相机切换轨直接绑定 HeadCamera 或 ThirdCamera 组件。
CinematicTime 由运行中的蓝图 Tick 应用。普通编辑状态拖动 Sequencer 时间线，不能保证骨骼随时间更新；
请通过 MRQ 复现序列，或在运行／模拟状态查看，不把静止的编辑器拖动预览误判为动作失效。

四、理想针孔相机参数

以下参数是仿真假设，不是实体头戴相机的实测标定。
图像宽 W=1920，高 H=1080，像素长宽比 1:1。
头戴水平 FOV=100°，对应垂直 FOV≈67.6727479708°。
fx = fy = (W/2) / tan(100°/2) = 805.5356459301888 px。
cx = 960.0 px，cy = 540.0 px，skew=0。

连续图像边界坐标下的 K：
  [805.5356459301888,   0,                  960]
  [  0,                805.5356459301888,  540]
  [  0,                  0,                 1]

像素坐标约定
  左上图像边界角为 (0,0)，x 向右、y 向下。
  第 col 列、第 row 行像素的中心坐标为 (col+0.5, row+0.5)。
  对应 UV=(u/W,v/H)，因此主点归一化坐标为 (0.5,0.5)。
  这称为“连续图像边界坐标”，不能与“左上像素中心为整数 (0,0)”混用。

与 OpenCV 常用整数像素中心坐标对接
  u_cv = u_edge - 0.5，v_cv = v_edge - 0.5。
  fx、fy 和畸变系数不变；cx_cv=959.5，cy_cv=539.5。
  使用 OpenCV 的 K 时应采用上述转换后的主点，或对全部采样坐标施加一致的 0.5 平移。
  不能只换坐标约定而保留旧主点，也不能在主点和采样位置两处重复减 0.5。

相机三维坐标转换
  UE 相机局部 +X 向前、+Y 向右、+Z 向上。
  采用常见视觉相机坐标时：X_cv=Y_UE，Y_cv=-Z_UE，Z_cv=X_UE。
  此关系针对相机局部坐标；世界坐标必须先通过相机位姿变换进入相机坐标系。

五、Brown–Conrady 畸变及材质实现

径向：k1=-0.12，k2=0.02，k3=0。
切向：p1=0.0005，p2=-0.0003。
令理想归一化坐标 x=(u-cx)/fx，y=(v-cy)/fy，r²=x²+y²：
  radial = 1 + k1*r² + k2*r⁴ + k3*r⁶
  xd = x*radial + 2*p1*x*y + p2*(r²+2*x²)
  yd = y*radial + p1*(r²+2*y²) + 2*p2*x*y
再用同一 K 将 xd、yd 转回输出图像坐标。

屏幕材质需要反向取样：从输出畸变像素求其理想源图坐标，因此图中展开 8 次固定点逆迭代，
随后采样原生 SceneTexture PostProcessInput0。材质使用 278 个原生可视化节点，无 Custom HLSL。
该实现按 k3=0 构建；如增加非零 k3，不能只改文档，必须扩展材质计算图并重新验证。
超出理想源图范围的位置填黑，不使用 overscan，也不裁切以隐藏黑边；边缘黑区是当前实现的明确行为。
畸变只作用于 HeadCamera；ThirdCamera 保持普通观察视角。

材质中的归一化参数
  FxOverWidth = 0.41954981558864
  FyOverHeight = 0.7458663388242489
  CxOverWidth = 0.5
  CyOverHeight = 0.5
另有 k1、k2、p1、p2 标量参数。
完整保存值见 Output/Validation/LensMaterial_Settings.json。

改变 FOV 或分辨率时
  FOV 改变后重新计算 fx、fy，并更新材质的 FxOverWidth、FyOverHeight，重新生成图像验证。
  若只按相同比例缩放分辨率且保持同一画幅，K 的像素单位值相同比例缩放，归一化参数保持不变。
  若改变宽高比、主点或非方形像素假设，必须重新推导相机投影与材质参数，不能沿用当前匹配关系。

六、验证证据与解释边界

现有独立双精度公式检查：91027 个采样点；有效源图范围最大残差约 0.0004565 px，阈值 0.01 px。
这只验证 8 次逆迭代的数学式，不等于 GPU 材质渲染误差，也不等于实体镜头标定精度。
图像验证比较四张实际渲染 PNG 的网格线、源图边界与场景对应关系。
已生成的 Lens_Render_Validation.json 以同一组系数在 OpenCV 中独立重采样无畸变网格，
再与 UE 原生材质输出比较：有效范围平均绝对误差约 1.235／255，像素误差第 95 百分位为 7／255；
网格边缘距离中位数为 0 px，第 95 百分位约 0.955 px；实际变化像素占比约 43.57%，检查结果通过。
图像采样、插值和 TAA 会影响像素差；不能把独立双精度公式的亚像素残差当成 GPU 图像的误差。
当前组件安装参数见 Deliverables/相机与导出参数.json；Final_Asset_Settings.json 为历史记录；当前 HeadCamera 水平 FOV=100°、ThirdCamera FOV=80°，
两者约束 16:9，且不使用 Pawn Control Rotation。精确安装变换见“挥杆与相机说明.txt”。
